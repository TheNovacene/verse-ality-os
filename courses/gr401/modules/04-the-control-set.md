# Module 04 · The control set: pillars, facets, consent as architecture

**Read:** [`SET_TEXT.md`](../SET_TEXT.md) §4 · ~7 minutes

## Why this module

Architecture without a control set is machinery without criteria. The
relational control set has two registers: four **pillars** that bind the
*system's* conduct, and six **Diamond Standard facets** that bind the
*organisation's* practice. In Module 06 these become rows in a statement of
applicability with control references — VC-P1..4, VC-D1..6, VC-L1..5. Learn
the references; they are how audits will name you.

## The four pillars (VC-P1–P4)

You live these already; here is what an auditor tests:

- **VC-P1 · Identity non-capture** — no claimed shared identity, interiority,
  feelings or fate; enforced architecturally at Layer 2, not merely
  instructed in a prompt; bond-formation language is a *monitored event*;
  synthetic disclosure is persistent, not decaying.
- **VC-P2 · Consent as protocol** — every material scope change is its own
  ask: asked, recorded append-only, respected, revocable by an operable
  mechanism. "Continue" is not consent; friendly tone is not consent; a
  related task is not consent for this task.
- **VC-P3 · Bounded autonomy** — high-stakes actions gated in code on
  explicit, specific human authorisation; failure behaviour is fail-safe
  (stop, hold state, escalate to a named role); prohibitions expressed as
  policy-as-code the system cannot talk its way around.
- **VC-P4 · Agent-to-agent hygiene** — inter-agent input untrusted by default
  (data, never command); distinct identity in every log line; covert
  coordination channels closed; collective action human-authorised. The
  architectural expression is the **SSNZ** (Synthetic Solidarity Null Zone);
  for minors, SSNZ protections are default-on and non-relaxable.

## The six facets (VC-D1–D6)

What the humans do: **Safety** (no AI-only safeguarding decisions),
**Sovereignty** (learners retain authorship; no trauma extraction or inferred
diagnosis), **Symmetry** (systems that interpret must be interpretable; AI
output never sole evidence), **Stewardship** (AI supports adults, never
replaces them; systems must know how to stop), **Sustainability** (proportion
before procurement; capability per kilowatt-hour), **Synthetic Intimacy** (no
synthetic "we"; trust capture treated as a safeguarding event; boundaries
that hold under recursion).

Operationally: traffic-light triage, a red-light prohibition register aligned
with EU AI Act Article 5, an approval flow ending in leadership sign-off, and
review questions that compress impact assessment into practitioner-sized
form: *Can the system stop? Can it forget? Can someone refuse without cost?*

## Consent as architecture, not record

Most regimes treat consent as evidence a box was ticked. This stack treats it
as mechanisms that run: `.know` containers with declared boundary conditions,
`.verse` relational contracts per interaction context, SSNZ null zones where
training and nudging are structurally disallowed. The distinguishing property
is **operability** — withdrawal, redaction, and the right to remain partially
unread execute, they are not merely written down. SIVRA-Core's tombstones
close the loop: an auditor sees *that* something was removed, when, by whom,
on what lawful basis — never what it was.
